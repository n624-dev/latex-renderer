# Web画面の情報設計と回帰確認

関連: #212、レスポンシブ共通対応 #53。

## 表示の原則

通常表示は「目的・現在の状態・主操作」を優先する。技術的な識別子、ハッシュ、内部設定、全項目のJSONは削除せず、詳細表示から確認・コピーできるようにする。表示名の翻訳でAPI値や権限を変更しない。

削除・失効・権限変更、認可、更新・復旧、TeX環境の構築に必要な警告は、操作の確認時に残す。繰り返す常設説明とは区別する。失敗の原因、保存期限、再試行条件は通常表示で確認できるようにする。

## 画面ごとの確認対象

- 公開ページ: アカウントの必要条件、すべての配布物、稼働状態と確認時刻。
- 文書: 既存URLと見出しの識別子、検索、コードのコピー、折り畳み内への直接リンク。導入手順と詳細仕様を分離する。
- 利用者アプリ: 既定のプロジェクト保存、出力選択、結果・ログ・SVG、改訂と改訂内の変換履歴。続きの取得に失敗しても同じカーソルから再試行する。
- 管理画面: 全ナビ項目、権限条件、補助・危険操作、所有者とサービスアカウント、キーの権限選択と一度限りの表示、完全な技術情報。
- 更新・TeX環境: 現在と候補の版、状態、負荷・停止の注意、ログ。ポーリングで利用者が選んだ開閉・スクロール状態を変えない。
- 認可・セットアップ: 接続元と許可する操作、認証方式に合う入力欄、診断結果、確認済み設定、復旧操作。秘密情報を要約・詳細データへ追加しない。

## CSSの確認

管理Webのバッチ実行中は、ファイル入力・実行先・内容の再確認を無効化する。
非同期の内容確認は最新の選択だけを反映し、予約応答を待っている間の中止も
Job作成後にサーバーへ伝える。再実行はAPIの返却IDを使い、応答喪失時には
同じ操作のIdempotency-Keyを再利用する。

監視・単体成果物・PDF一括取得・キャンセルは期限付きJobチケットの更新を共通化する。
更新は認証済み管理セッションとCSRF検証を必要とし、元APIキーの失効・権限と
成果物の保存期限を緩和しない。接続エラーはJobの変換失敗と区別し、再ログイン後は
「監視を再開」で既存Jobを再確認できる。新しいJobを暗黙に作成しない。

`tests/browser/control-layout.browser.ts` は #212 の CSS-01〜28 に対応する共通部品を検証する。操作間隔、表のセル・最終行、SVG詳細と隣接ボタン、コードのコピー位置、ナビのキーボードフォーカス、ダイアログ、チェック項目、ファイル入力、無効状態、グリッド余白、空の通知、定義リスト、技術情報の改行を含む。

`tests/browser/admin-information.browser.ts` は実際の管理画面スクリプトとCSSを使用し、画面幅390・768・960・1200pxと200%のレイアウト拡大、明示したサービスアカウントの選択、キー発行のCSRF、詳細表示維持、API資料からのログアウトを確認する。

文書は `docs-layout.browser.ts`、利用者のページ送りは `app-pagination.browser.ts`、更新ログは `update-log.browser.ts`、クライアント設定は `client-setup-information.browser.ts`、サーバー設定は `server-setup.browser.ts` で補う。Chromiumとタッチ設定のWebKitをCIで実行する。

これらはfixture・ブラウザでの回帰テストであり、物理端末のソフトキーボード、ピンチ拡大、外部認証事業者、実環境での更新・復旧の受入試験を代替しない。画面サイズや表示エンジンの追加時も、この区別を維持する。
