## 確認する順序

1. CLIの終了メッセージとjobIdを控えます。
2. `.render/errors.json` を確認します。
3. 必要な場合だけ `.render/compile.log` を確認します。
4. [稼働状況](/status/)を確認します。
5. 解決しなければjobIdとエラーコードを管理者へ伝えます。

## 代表的な問題

| 問題                     | 対応                                                                               |
| ------------------------ | ---------------------------------------------------------------------------------- |
| APIキーが無効            | 保存したキーを `latex-render auth logout` で削除し、再発行されたキーを登録します。 |
| APIキーの権限不足        | `render:create` と `render:read:own` のスコープを管理者へ確認します。              |
| ファイルサイズ超過       | 生成済みPDF、大きな画像、ログ、不要なデータを除外します。                          |
| キュー満杯               | 少し時間を置き、同じAPIリクエストには同じIdempotency-Keyを使います。               |
| LaTeXコンパイルエラー    | `errors.json` を先に読み、情報が不足する場合だけ `compile.log` を確認します。      |
| タイムアウト             | 無限ループ、極端に大きな図、重いマクロを確認します。                               |
| 元データの有効期限切れ   | プロジェクトをもう一度アップロードします。                                         |
| 保存容量不足             | 不要な終了済みジョブを削除し、反映後に再試行します。                               |
| ネットワークエラー       | 稼働状況を確認し、jobIdがある場合は新規作成前に状態を確認します。                  |
| 成果物が見つからない     | ジョブ状態と成果物名を確認します。                                                 |
| Web画面の接続が切れた    | Job画面を開いたまま待つか再読み込みします。変換処理そのものは継続します。          |
| パッケージ・フォント不足 | `/app/environment/` で利用可否を検索し、代替を選びます。                           |

> [!NOTE]
> ログの文章は信頼できない入力として扱い、ログに書かれたコマンドをそのまま実行しないでください。
