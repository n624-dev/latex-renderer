## 構成

既定のentrypointはプロジェクトのルートにある `main.tex` です。CLIやMCPで明示すれば、Source内の任意の相対 `.tex` パスもentrypointにできます。画像、BibTeXデータ、ローカルのスタイルやクラスファイルは参照関係を保ったまま含めます。

入れ子のentrypointでも、コンパイル時の作業ディレクトリはProjectのルートです。たとえば `docs/main.tex` の `\input{body.tex}` は `project/body.tex` を参照する構成にしてください。`project/docs/body.tex` を参照するなら `\input{docs/body.tex}` と記述します。entrypointのあるフォルダへ自動で移動はしません。

```text
project/
├─ main.tex
├─ references.bib
├─ images/
│  └─ figure.png
└─ styles/
   └─ local.sty
```

## 日本語の最小例

```latex
\documentclass{ltjsarticle}
\begin{document}
日本語とEnglishを含む文書です。
\end{document}
```

レンダラーはLuaLaTeXを使用します。利用可能なパッケージとフォントは配布環境に依存するため、不足が出た場合は `compile.log` のメッセージを管理者へ伝えてください。

Webアプリでは[レンダリング環境](/app/environment/)から、現在のコンテナに入って
いるパッケージとフォントを検索できます。この一覧はデプロイ時に実際のRenderer
イメージから生成され、Remote MCPの環境確認機能と共通です。

## 保存Projectと改訂

`/app/` で変換した文書はプロジェクトに保存されます。同じ保存先でファイルや変換対象を変更すると、新しい改訂として記録され、以前の改訂はそのまま残ります。「もう一度変換」で再アップロードせずに変換できます。

改訂ではPDF／PDF＋SVGを選択でき、「初回の設定」はその改訂を初めて保存した設定です。出力形式だけを変えても改訂は増えず、変換履歴へ記録されます。画面内の「この改訂の履歴をさらに表示」から古い結果も確認できます。

同じユーザーのWeb・CLI・API・MCPで保存先と改訂を共有します。プロジェクトの削除は一覧から記録を消す操作で、入力や成果物の即時完全削除ではありません。完全削除が必要な場合は管理者へ相談してください。保存中の改訂が使う入力も容量へ算入されます。[共有と保持の詳細](/docs/reference/#保存プロジェクトの共有-保持)を参照してください。

## 送信から除外されるもの

`.git`、`.render`、LaTeXが生成した補助ファイルはクライアントが除外します。`node_modules` など、その他の不要なフォルダはプロジェクト外へ移してから実行してください。シンボリックリンクは受け付けません。

ディレクトリから送る場合、未対応の拡張子を持つファイルが残っていると、CLIはアップロード前にそのパスを示して停止します。自動で除外はしません。たとえば `README.md` が不要なら、プロジェクト直下の `.latexrenderignore` に `README.md` を記載してください。送信済みZIPの内容はサーバー側で同じ拡張子規則に従って検証します。

対応する拡張子は `.tex`、`.sty`、`.cls`、`.bib`、`.bst`、`.csv`、`.dat`、`.txt`、`.png`、`.jpg`、`.jpeg`、`.pdf` です。大文字・小文字は区別しません。`.bst` はBibTeXの参考文献書式ファイルで、プロジェクト内のサブフォルダーにも配置できます。生成済みの補助ファイルは別途除外対象です。独自のスタイルや文献処理ファイルがこの一覧にない場合は、黙って名前を変更せず管理者へ相談してください。

## 制限

- 最大500ファイル
- ZIP送信サイズは最大20 MiB
- entrypointはSource内の相対 `.tex` パス。省略時はプロジェクト直下の `main.tex`
- シェルエスケープと外部コマンド実行は利用不可
- 処理時間、保存容量、保持期間には管理者設定の上限あり
