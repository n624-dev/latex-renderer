## Учётные данные {#資格情報}

- Не включайте ключи API в аргументы команд (они видны, в частности, через `ps`), URL, репозитории Git, журналы или переписку с ИИ.
- Для локального хранения используйте DPAPI в Windows или файл с режимом `0600`, доступный для чтения только владельцу, в Linux и macOS.
- Используйте пароли для входа через браузер, секреты OIDC и файлы cookie сеанса только по назначению. Храните отдельно ключи CLI и API (`lrk_` и `lra_`).

## Проекты {#プロジェクト}

Все исходники LaTeX и вложения считаются недоверенными входными данными. Символические ссылки, доступ к оболочке из TeX, выполнение внешних команд и сетевые соединения за пределами контейнера отключены. Соблюдайте изоляцию, ограничения времени и файловые лимиты.

## Публичные разделы и администрирование {#公開領域と管理領域}

Публичные документация и загрузки, защищённые страницы (`/app/` и `/admin/`) и API рендеринга имеют разные маршруты в пределах одного канонического источника HTTPS.

- **Сетевая граница.** Единственная точка входа в профиле Cloudflare — Tunnel/Workers, в профиле standalone — обратный TLS-прокси. Все прикладные службы прослушивают интерфейс обратной петли. Внутренний API, SQLite и сокеты управления закрыты от внешнего доступа. Защищённые разделы исключены из индексов поисковых систем.
- **Аутентификация и сеансы браузера.** Для идентификации через внешний IdP требуется точное совпадение `provider + issuer + subject`. Адрес электронной почты и отображаемое имя не используются для автоматического связывания учётных записей. Сервер может немедленно отозвать сеанс. Для запросов, изменяющих состояние, требуются точное совпадение `Origin` и токен CSRF данного сеанса. Пароли защищены с помощью `scrypt` и дополнительного секрета (pepper), принадлежащего root. В публичных установках ограничьте соединения и частоту запросов на прокси и используйте защиту провайдера от DDoS.
- **Remote MCP.** `/mcp`, конечная точка токенов OAuth и метаданные обнаружения доступны публично. Выполнение инструментов требует краткоживущего токена Bearer с ограниченными аудиторией и областью доступа. Авторизация использует сеанс браузера `/app/` и явно связывает доступ с существующим активным пользователем.
  - Стандартный ответ (`content`) содержит лишь идентификаторы в пределах владельца, состояния, курсоры и ограниченную диагностику, необходимые для продолжения работы. Пути и диагностика, полученные от пользователя, возвращаются как недоверенные данные без управляющих символов, с ограничениями длины и количества.
  - Стандартное содержимое `content` и диагностические журналы исключают токены OAuth, ключи API, билеты, необработанные данные base64, полные исходники и журналы, трассировки стека, идентификаторы subject из Access и внутренние пути сервера. Полные PDF и журналы доступны только через чтение ресурсов с повторной проверкой владельца.

## Локальный веб-интерфейс настройки {#local-setup-web-ui}

`n624-latex setup --gui` (ранее `latex-render setup --gui`) прослушивает только случайный порт на `127.0.0.1` локального компьютера.

- Фрагмент (`#...`) URL, открываемого CLI, содержит одноразовый стартовый токен. Браузер немедленно удаляет его из истории и обменивает на краткоживущий сеанс.
- Для всех операций API требуются точное совпадение `Origin`, сеанс Bearer и отдельный токен CSRF. CORS отключён, проверяются Host и адрес обратной петли клиента, применяются строгая CSP, `frame-ancestors 'none'` и `no-store`.
- Введённый ключ передаётся только операции сохранения и не попадает в ответы проверки состояния, диагностики и тестового преобразования. Интерфейс закрывается после 30 минут бездействия или через 2 часа после запуска.
