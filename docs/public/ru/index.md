## Создайте свой первый PDF {#最短でpdfを作る}

1. Откройте [веб-приложение](/app/) и войдите способом, который указал администратор.
2. Выберите файл `.tex` и нажмите **Преобразовать в PDF**. Если в документе есть изображения или библиография, упакуйте их вместе с документом в ZIP-архив и выберите этот архив.
3. Откройте PDF на странице результатов. Позже его можно найти в разделе **История** веб-приложения.

Если у вас нет тестового документа, сохраните этот пример в файле `main.tex` в кодировке UTF-8.

```latex
\documentclass{article}
\begin{document}
Hello, LaTeX!
\end{document}
```

- [Пример на японском и структура ZIP-архива](/ru/docs/projects/)
- [Руководство по веб-приложению](/ru/docs/web/)
- [Сохранение PDF и PNG и повторное извлечение SVG](/ru/docs/outputs/)

Для работы в терминале [установите CLI для вашей системы](/ru/docs/client/). Настройте подключение с помощью `n624-latex setup`. В каталоге, где вы сохранили `main.tex`, выполните `n624-latex main.tex`, чтобы создать `main.pdf`.

## Что потребуется {#必要なもの}

- **Веб-приложение и Remote MCP.** Нужна учётная запись с указанным администратором способом входа.
- **CLI, Local MCP и HTTP API.** Запросите у администратора ключ API рендеринга с префиксом `lrk_`.
- **Требования CLI в зависимости от способа установки**
  - Debian и Ubuntu с APT: пакет включает собственную версию Node.js.
  - macOS с Homebrew: Homebrew устанавливает нужную версию Node.js.
  - Загружаемый установщик для Windows, macOS или Linux: требуется Node.js версии 24 или новее.

Документы компилируются на сервере. Для любого из этих способов можно обойтись без установки TeX Live на свой компьютер.

> [!WARNING]
> Не вставляйте ключи API в переписку с ИИ, исходный код, репозитории Git или журналы. При подозрении на утечку немедленно попросите администратора отозвать ключ и выдать новый.

Если не удаётся войти или преобразовать документ, см. [Устранение неполадок](/ru/docs/troubleshooting/).
