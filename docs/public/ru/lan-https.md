## Доступ через локальный IP-адрес {#lan-の-ip-アドレスからアクセスする}

Akebi преобразует частный IP сервера в имя хоста, доступное по HTTPS.

Настройте общий сервис сертификатов в мастере LaTeX Renderer. Чтобы развернуть собственный сервис, см. [Эксплуатация сервиса сертификатов Akebi](/ru/docs/lan-https-authority/).

- **Пример IPv4.** Для IP `192.168.1.50` и домена локальной сети `lan.example.org` адрес будет `https://192-168-1-50.lan.example.org`.
- **IPv6.** Имя содержит все восемь групп поддерживаемого частного адреса в развёрнутой форме. Используйте точный URL из мастера настройки.

**Требования к сети и DNS**
Клиент должен иметь доступ к локальной сети сервера. Если имя не разрешается, проверьте, не блокирует ли маршрутизатор или DNS-резолвер ответы с частными IP в рамках **защиты от DNS rebinding**. При необходимости добавьте исключение только для используемого домена локальной сети.

## Выбор типа сертификата {#証明書の方式を選ぶ}

| Метод | Требования и особенности |
| --- | --- |
| **Общий сервис, публичный УЦ** | Настройте общий сервис и примите условия удостоверяющего центра (УЦ). Закрытый ключ сертификата остаётся на сервере. |
| **Собственный сервис, публичный УЦ** | URL и домен локальной сети [вашего сервиса Akebi](/ru/docs/lan-https-authority/) и при необходимости код приглашения. |
| **Keyless** | Требуется совместимый сервис, которому передаётся операция подписи во время установления TLS-соединения. |
| **Существующий сертификат или частный УЦ** | Сертификат для имени сервера и соответствующий закрытый ключ. Для частного УЦ настройте доверие к корневому сертификату на сервере и всех клиентах. |

> [!NOTE]
> - Если используется публичный УЦ, имена хостов из выпущенных сертификатов попадают в **открытые журналы прозрачности сертификатов (CT)**.
> - Две физически разные локальные сети с одинаковыми частным IP и доменом локальной сети считаются для браузера **одним источником** и используют общие cookie и другие сохранённые данные.

## Настройка доступа из локальной сети {#lan-向けに設定する}

1. При новой установке [подготовьте сервер](/ru/docs/self-hosting/#準備するもの) и откройте [мастер](/ru/docs/server-setup/#ブラウザで開く) командой `sudo n624-latex server setup --web`. Для изменений на сервере с управляемым выделенным HTTPS используйте `sudo n624-latex server setup --ingress --web`.
2. Выберите **LAN** в качестве способа доступа и укажите сетевой интерфейс, частный IP, разрешённые подсети клиентов и порт HTTPS.
3. Выберите сервис и способ получения сертификата. В общем сервисе задаются URL `https://akebi.n624.net` и домен `lan.n624.net`, а сервер регистрируется при применении изменений. Приглашение не нужно. Для публичного УЦ ознакомьтесь с условиями и примите их. Для своего сервиса с приглашениями введите код администратора.
4. Перед применением проверьте сформированный HTTPS-адрес и разрешённые подсети. Аутентификация приложения по паролю или OIDC продолжает действовать.
5. С другого устройства в разрешённой подсети откройте URL, проверьте отсутствие предупреждений о сертификате, войдите и преобразуйте тестовый документ.

Для развёртывания собственного сервиса см. [Эксплуатация сервиса сертификатов Akebi](/ru/docs/lan-https-authority/).

## Проверка состояния сертификата {#証明書の状態を確認する}

Эти команды показывают службу, таймер продления и журналы её пространства имён.

```bash
systemctl status latex-renderer-lan-https.service latex-renderer-lan-renew.timer
sudo journalctl --namespace=latex-renderer-lan --since '1 hour ago'
```

Если выпуск или продление не удались, проверьте часы сервера, HTTPS-соединение с сервисом, домен, IP и указанное УЦ время следующей попытки. При временном сбое действующий сертификат сохраняется. Таймер продолжит выпуск из сохранённого состояния. Если ключ и состояние расходятся, проверьте сохранённые файлы состояния того же поколения.

См. [Устройство Akebi и устранение неполадок](https://github.com/n624-dev/latex-renderer/blob/main/docs/akebi-lan-https.md).
