## Структура проекта {#構成}

- **Документ из одного файла.** Загрузите `.tex` непосредственно в веб-приложение или выполните `n624-latex main.tex` в CLI.
- **Документ с изображениями, библиографией или несколькими исходными файлами.** Соберите всё в **один ZIP-архив** с сохранением относительных путей. В CLI также можно указать каталог.
- **Создание ZIP.** Выберите для упаковки содержимое папки, например `main.tex` и `images/`. Если упаковать и родительскую папку, при преобразовании потребуется указать точку входа вида `project/main.tex`.

```text
project/
├─ main.tex
├─ references.bib
├─ images/
│  └─ figure.png
└─ styles/
   └─ local.sty
```

**Точка входа и относительные пути**
По умолчанию главный документ — `main.tex` в корне проекта. Даже если выбрать `.tex` в подкаталоге, например `docs/main.tex`, **рабочим каталогом компиляции всегда остаётся корень проекта**. Чтобы из `docs/main.tex` подключить расположенный рядом файл `body.tex`, напишите `\input{docs/body.tex}`. При записи `\input{body.tex}` компилятор будет искать `body.tex` в корне.

## Минимальный пример на японском {#日本語の最小例}

По умолчанию используется **LuaLaTeX**. Чтобы проверить набор японского текста, сохраните следующее содержимое в `main.tex` в кодировке UTF-8.

```latex
\documentclass{ltjsarticle}
\begin{document}
日本語とEnglishを含む文書です。
\end{document}
```

Ищите доступные пакеты и шрифты в [среде рендеринга](/app/environment/). Список формируется из серверного контейнера при развёртывании и используется также для поиска через Remote MCP. Если пакета не хватает, передайте администратору соответствующее сообщение из `compile.log`.

## Сохранённые проекты и ревизии {#保存projectと改訂}

Документы, преобразованные в веб-приложении (`/app/`), сохраняются в проектах.

- **Автоматическая регистрация ревизий.** Каждое новое сочетание содержимого, главного документа, движка и выходных форматов сохраняется как ревизия проекта. Прежние ревизии остаются в истории.
- **Повторное преобразование ревизии.** Нажмите **Конвертировать снова**, чтобы использовать сохранённые документ и движок. Если изменить здесь выходной формат, результат добавится в историю преобразований той же ревизии.
- **Совместное использование и удаление.** Веб-приложение, CLI, HTTP API и MCP используют общие проекты и ревизии пользователя. Удаление проекта скрывает его запись. Имеющиеся исходники и результаты удаляются по истечении срока хранения. Для немедленного полного удаления обратитесь к администратору. Исходники, на которые ссылаются активные ревизии, учитываются в квоте пользователя. См. [Совместное использование и хранение](/ru/docs/reference/#保存プロジェクトの共有-保持).

### Редактирование в браузере {#ブラウザーで編集する}

Откройте сохранённый проект и выберите **Редактировать TeX**. Изменения сохраняются в черновике. После паузы при вводе начинается компиляция, и в случае успеха PDF обновляется. При ошибке предварительного просмотра можно открыть последний готовый PDF и узнать, какой версии черновика он соответствует.

В новых проектах файл `main.tex` изначально пуст. Пока главный документ пуст, можно начать с шаблона. Чтобы продолжить с сохранённой версии, выберите **Редактировать с этой ревизии**. Если черновик уже существует, подтвердите его замену.

Для компиляции по запросу отключите **Автокомпиляция** и нажимайте **Скомпилировать**. Выберите **Результаты сохранённой версии** и нажмите **Сохранить версию**, чтобы сохранить черновик и настройки. Если требуются SVG, откройте сохранённую ревизию и нажмите **Конвертировать снова**.
При редактировании видны состояние компиляции и предварительный просмотр.

## Исключение файлов при загрузке {#送信から除外されるもの}

- **Автоматические исключения.** CLI пропускает `.git`, `.render` и вспомогательные файлы LaTeX, например `.aux`. Символические ссылки отклоняются.
- **Неподдерживаемые файлы.** Переместите ненужные папки, например `node_modules`, за пределы проекта. При загрузке каталога с неподдерживаемыми расширениями CLI покажет путь и остановится. Чтобы оставить в проекте такой файл, как `README.md`, но не отправлять его, добавьте в `.latexrenderignore` в корне проекта строку `README.md`. Сервер проверяет расширения в ZIP по тем же правилам.
- **Разрешённые расширения** (без учёта регистра)
  `.tex`, `.sty`, `.cls`, `.bib`, `.bst`, `.csv`, `.dat`, `.txt`, `.png`, `.jpg`, `.jpeg`, `.pdf`
  Файлы `.bst` задают библиографические стили BibTeX и могут находиться в подкаталогах. Если пользовательский стиль имеет другое расширение, обратитесь к администратору, прежде чем менять его.

## Ограничения {#制限}

- **Число файлов.** Не более 500.
- **Размеры по умолчанию.** ZIP — 20 МиБ, распакованные файлы в сумме — 100 МиБ, отдельный файл — 20 МиБ.
- **Точка входа.** Относительный путь к файлу `.tex` среди исходников. По умолчанию используется `main.tex` в корне.
- **Безопасность.** Доступ к оболочке из TeX (в том числе `\write18`), запуск внешних команд и внешние сетевые соединения отключены.
- **Ресурсы.** Администратор определяет лимиты времени, объём хранилища на пользователя и срок хранения результатов.
