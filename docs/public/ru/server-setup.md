## Выбор способа настройки {#どの手順を使うか}

Для новой установки [подготовьте сервер](/ru/docs/self-hosting/#準備するもの) и откройте мастер в **браузере**. На существующей установке тот же мастер меняет способ входа и ограничения выполнения.

- Выполните на сервере `sudo n624-latex server setup --plan` для проверки нужных пакетов и свободного места. Устраните отмеченные проблемы и повторите проверку.
- Чтобы изменить существующую установку с выделенным HTTPS или HTTPS в локальной сети (Akebi), добавьте `--ingress` к команде запуска.
- Если на минимальном хосте Docker сообщает об отсутствующих модулях ядра, выполните рекомендации и попробуйте снова. Например, если требуется `nf_tables`, администратор должен выполнить `sudo modprobe nf_tables`.

## Открытие в браузере {#ブラウザで開く}

Подключитесь по SSH под непривилегированной учётной записью развёртывания и выполните команду. **Не закрывайте терминал до окончания настройки.**

```sh
sudo n624-latex server setup --web
```

1. При первоначальной установке ознакомьтесь со списком подготовительных действий и введите `PREPARE` для продолжения. Дождитесь скачивания подписанной версии, подготовки служб, создания и проверки первой среды TeX.
2. Найдите в терминале одноразовый URL. Он действителен **5 минут**.
3. Откройте его на сервере или используйте **перенаправление порта SSH**, чтобы обратиться к тому же порту со своего компьютера. Если указан порт `41234`, выполните команду ниже в другом локальном терминале и откройте в браузере URL из мастера.

```bash
ssh -N -L 127.0.0.1:41234:127.0.0.1:41234 admin@latex.example.com
```

> [!WARNING]
> Не передавайте URL настройки другим и не публикуйте его порт в интернете или через обратный прокси.

## Проверка и применение конфигурации {#プレビューから適用まで}

1. **Выберите способ доступа и входа.** Для новой установки настройте HTTPS и первого владельца. Введите пароли и секреты клиента OIDC в соответствующие скрытые поля.
2. **Проверьте предварительный результат.** Уточните публичный URL и способ входа. При смене способа подготовьте идентификатор владельца для нового метода, пока прежний вход ещё работает.
3. **Примените изменения.** Дождитесь запуска или перезапуска служб.
4. **Войдите и создайте PDF.** Используйте отдельное окно браузера, чтобы [проверить установку](/ru/docs/self-hosting/#導入完了の確認).

Если в новой установке включаются и пароли, и OIDC, сначала зарегистрируйте владельца с паролем и добавьте к той же записи значения OIDC `issuer` и `subject`. В ограничениях выполнения порог запуска задаёт объём свободной оперативной памяти перед началом задания, а рабочий лимит — объём памяти, доступный контейнеру.

## Проверка прерванного изменения {#中断した変更を確認する}

- Если соединение оборвалось после начала применения конфигурации, сначала проверьте результат той же операции.
- Если процесс мастера завершился, снова запустите его для той же установки и выберите **Recover** в веб-интерфейсе или **`RECOVER`** в терминале. Если владелец уже зарегистрирован, мастер использует его запись и продолжит до подтверждения. Такое восстановление конфигурации не загружает прежнюю копию базы данных.
- Файлы восстановления могут содержать секреты TLS или OIDC. Не редактируйте их вручную. При обращении за помощью укажите только отображаемые код ошибки и этап.

## Открытие в терминале {#端末で開く}

```sh
sudo n624-latex server setup --cui
```

При изменении существующего сервера задайте параметры по очереди или нажмите Enter в пустом поле, чтобы оставить прежнее значение. Для автоматического HTTPS в локальной сети при установке выберите `LAN` и следуйте подсказкам. При первоначальной настройке собственного HTTPS или настройке имеющегося маршрута Cloudflare в терминале введите JSON указанного формата одной строкой. Если настраиваете впервые, [начните в браузере](#ブラウザで開く).

### Прежние версии и ручная установка {#旧版-手動配置の場合}

> [!DETAILS] Прямой запуск server-setup.mjs
>
> Если вы подготовили сервер без APT, настроили отдельного пользователя, Node.js и Docker без root и поместили проверенную версию в `/opt/latex-renderer/current`, вызовите `server-setup.mjs` напрямую. Для подготовки нового хоста см. [Инструкции по ручной установке](/ru/docs/self-hosting/#現在の提供状況).
>
> | Задача | Аргумент запуска | Условия |
> | --- | --- | --- |
> | Изменить существующую аутентификацию или лимиты | `--existing` | Владелец зарегистрирован, службы работают |
> | Настроить и зарегистрировать первого владельца | `--initial` | Дистрибутив и среда подготовлены, рабочая конфигурация и прежняя база отсутствуют |
> | Изменить управляемый выделенный HTTPS | `--ingress` | Выделенный HTTPS в профиле standalone. Переход с общего Nginx выполняется отдельно. |
>
> - **Интерфейс терминала**
>   ```bash
>   sudo /usr/local/bin/node /opt/latex-renderer/current/deploy/scripts/server-setup.mjs --cui --existing
>   ```
> - **Интерфейс браузера**
>   ```bash
>   sudo /usr/local/bin/node /opt/latex-renderer/current/deploy/scripts/server-setup.mjs --web --existing
>   ```

См. [Спецификация входных параметров и восстановления мастера](https://github.com/n624-dev/latex-renderer/blob/main/docs/server-settings-wizard.md).
