В папке с файлом `main.tex` выполните `n624-latex main.tex`, чтобы сохранить там же PDF. При первом использовании [установите CLI](/ru/docs/client/) и настройте подключение.

## Аутентификация {#認証}

Откройте настройки в браузере, чтобы сохранить ключ API.

```sh
n624-latex setup --gui
```

Если открыть браузер нельзя, например в сеансе SSH, зарегистрируйте ключ через **стандартный ввод**, чтобы он не появился в аргументах команды. В Bash или Zsh выполните первую строку, вставьте ключ, нажмите Enter и выполните оставшиеся строки.

```sh
read -rs render_key
printf '%s' "$render_key" | n624-latex auth login --api-key-stdin
unset render_key
```

В Windows также доступен [скрытый ввод в установщике](/ru/docs/windows/#インストール).

Следующие команды соответственно проверяют наличие сохранённого ключа и удаляют его.

```sh
n624-latex auth status
n624-latex auth logout
```

`auth status` показывает адрес фактически используемого сервера и источник учётных данных: имя сохранённого профиля, переменную окружения `LATEX_RENDER_API_KEY` или отсутствие данных. С флагом `--json` доступны поля `origin` и `credentialSource`.

- Если задана переменная среды `LATEX_RENDER_API_KEY`, она имеет приоритет перед локальным ключом.
- `logout` удаляет лишь локально сохранённый ключ. При необходимости отдельно отмените переменную среды или отзовите ключ на сервере.

### Выбор сервера {#接続先サーバー}

По умолчанию CLI подключается к размещённому сервису (`https://latex-render.n624.jp`). Для своего сервера задайте его HTTPS-адрес в том сеансе терминала, где будете выполнять команды.

- Не добавляйте к URL суффиксы `/app/` и `/api/v1/`.
- Используйте ключ API, выданный этим сервером.

**Linux / macOS**

```sh
export LATEX_RENDER_BASE_URL=https://latex.example.com
```

**Windows PowerShell**

```powershell
$env:LATEX_RENDER_BASE_URL = 'https://latex.example.com'
```

## Настройка и диагностика {#セットアップと診断}

Откройте настройки подключения и интеграций с помощью `n624-latex setup`. При проблемах с подключением сначала проверьте состояние следующими командами. Если `n624-latex` не найдена, см. [Установка и PATH](/ru/docs/troubleshooting/#インストール-ログイン).

```sh
n624-latex setup status
n624-latex doctor
```

`doctor` проверяет установку и учётные данные в режиме чтения и не выводит значение ключа API. При обнаружении проблем возвращается код выхода `2`.

| --- | --- |
| APT | [Обновите через APT](/ru/docs/client/#apt-版の更新) или [переустановите](/ru/docs/client/#状態確認と修復) повреждённые пакеты. [Зарегистрируйте Local MCP вручную](/ru/docs/mcp/#local-mcpの登録). |
| Homebrew | [Обновите через Homebrew](/ru/docs/client/#homebrew-版の更新) или [переустановите](/ru/docs/client/#状態確認と修復) повреждённые пакеты. Настройте интеграции ИИ с помощью `n624-latex setup`. |
| Загружаемый установщик | [Обновите из настроек](/ru/docs/client/#配布インストーラー版の更新). Восстановите управляемые интеграции и сценарии запуска с помощью `n624-latex setup repair`. |

Для удаления воспользуйтесь [инструкцией для вашего способа установки](/ru/docs/client/#アンインストール). Интерфейс настройки работает локально и закрывается при выходе из CLI.

## Рендеринг {#レンダリング}

### Прямое преобразование файла TeX {#tex-ファイルを直接変換する}

Укажите `.tex` в каталоге проекта, чтобы создать PDF. Ссылайтесь на изображения, библиографию и локальные `.sty` по относительным путям.

```sh
n624-latex main.tex
n624-latex chapters/report.tex -o build/report.pdf
```

- Если не указать `-o`, PDF с тем же базовым именем, например `main.pdf`, сохранится в каталоге запуска команды.
- При ошибке LaTeX выводятся файл, строка и идентификатор задания, которые удалось определить. Если компиляция или скачивание не удались, последний успешно сохранённый PDF остаётся на месте.

#### Выбор движка LaTeX {#latex-のエンジンを選ぶ}

Чтобы использовать XeLaTeX, запишите имя движка перед именем файла.

```sh
n624-latex xelatex main.tex
```

Если движок не указан, CLI ищет в начале документа `% !TeX program = xelatex` или
`% !TEX TS-program = xelatex`. Если директив нет, проверяется
`.n624-latex.json` в корне проекта. Этот файл можно хранить
в Git, чтобы на разных компьютерах использовался один и тот же движок.

```json
{"engine":"xelatex"}
```

По умолчанию используется LuaLaTeX. Для pLaTeX и upLaTeX
в среде выполнения сервера должна быть установлена коллекция для японского языка.

| Движок | Что проверить при переносе документа |
| --- | --- |
| LuaLaTeX | Проверьте настройки документов, использующих `fontspec` или LuaTeX-ja. |
| pdfLaTeX | `fontspec` не поддерживается. Используйте настройки шрифтов для pdfLaTeX. |
| XeLaTeX | Поддерживает `fontspec`. Проверьте, нет ли пакетов, рассчитанных только на LuaTeX. |
| pLaTeX / upLaTeX | Используйте японский класс документа для выбранного движка. Для `jsarticle` в upLaTeX укажите опцию класса `uplatex`. |

Обработка библиографии зависит от пакетов и конфигурации документа. Включите `.bib` и собственные `.bst`. В документах BibTeX для pLaTeX и upLaTeX используются соответственно pBibTeX и upBibTeX. Результаты проверки PDF, SVG и координат SVG приведены в [среде рендеринга](/app/environment/).

### Преобразование ZIP или получение нескольких выходных файлов {#zip-複数の出力を指定する}

Используйте подкоманду `render` для преобразования ZIP или скачивания полного набора результатов, включая журналы, изображения страниц и SVG.

```sh
n624-latex render [directory-or-zip] [--entrypoint main.tex] [--output .render] [--open] [--svg]
```

**Примеры**

```sh
# Compile main.tex in the current directory and open the completed PDF
n624-latex render . --open

# Choose the main document in a ZIP and generate both PDF and SVG
n624-latex render ./report.zip --entrypoint reports/report.tex --output .render/report --svg
```

- Путь по умолчанию — текущий каталог, значение `--entrypoint` по умолчанию — `main.tex`. CLI подготавливает входной набор из не более чем 500 файлов и ожидает завершения. Точкой входа может служить относительный путь к файлу `.tex`. Сервер проверяет безопасность пути и наличие файла.
- С `--svg` также извлекаются внешние математические выражения и рисунки TikZ верхнего уровня в виде отдельных SVG.

### Повторное использование исходников для нескольких документов {#同じ入力から複数の文書を作る-source-の再利用}

Если в каталоге или ZIP несколько главных документов, загрузите исходники один раз с помощью `source upload` и повторно используйте их идентификатор. Для каждого задания указывайте отдельную выходную папку (`--output`).

```sh
n624-latex source upload ./project.zip --json
n624-latex render --source source_... --entrypoint reports/a.tex --output .render/a
n624-latex render --source source_... --entrypoint reports/b.tex --output .render/b
```

> [!DETAILS] Очистка каталога назначения, исключения и повторные загрузки
>
> - **Очистка прошлых результатов.** При повторном использовании каталога удаляются только PDF, изображения страниц и SVG, которые значились в прежнем `job.json` и отсутствуют в новом результате. Пользовательские файлы, не относящиеся к заданию, сохраняются.
> - **Проверка места назначения.** Пути с символическими ссылками отклоняются. В системах POSIX проверяются также владелец и права записи для группы и прочих пользователей. В Windows проверка битов режима POSIX пропускается.
> - **Исключение выходного каталога.** Если `--output` обозначает подкаталог проекта, из следующего ZIP исключается именно этот каталог. Папки с похожими именами остаются в архиве. Корень проекта нельзя использовать в качестве места назначения.
> - **Повторные загрузки.** Если сервер хранит действительный ZIP с тем же владельцем и SHA-256, он вернёт `uploadRequired: false` и пропустит передачу. Только этот владелец может использовать идентификатор исходников в дальнейших заданиях.

## Сохранённые проекты и ревизии {#保存projectと改訂}

С помощью CLI можно управлять сохранёнными на сервере проектами и ревизиями и повторно их компилировать. Проекты общие для веб-приложения, API, MCP и других ключей того же пользователя. Для временных операций `render` и `source upload` не требуется сохранять проект.

```sh
n624-latex projects list
n624-latex projects create <name>
n624-latex projects save <projectId> ./project --entrypoint main.tex --name <revision-name>
n624-latex projects get <projectId>
n624-latex projects jobs <projectId> <revisionId>
n624-latex projects render <projectId> <revisionId>
n624-latex projects rename <projectId> <name>
n624-latex projects delete <projectId> --yes
```

- **`save`** подготавливает каталог или ZIP в качестве входного набора и сохраняет в проекте неизменяемую ревизию. С `--svg` начальные форматы вывода ревизии — PDF и SVG.
- **`render`** создаёт задание из сохранённой ревизии. Только `--svg` переопределяет параметры вывода.
- **`list`, `get` и `jobs`** принимают `--cursor` для получения следующей страницы.
- **`delete`** скрывает проект в списке. Существующие задания не удаляются немедленно.

## Операции с заданиями {#ジョブ操作}

```sh
n624-latex jobs get <jobId>
n624-latex jobs cancel <jobId>
n624-latex jobs download <jobId> --output .render
n624-latex jobs download <jobId> --pdf-only --output .render
n624-latex jobs download <jobId> --preview-page 2 5 --output .render
n624-latex jobs retry-svg <jobId> --output .render
n624-latex jobs delete <jobId> --yes
```

- **Скачивание и ожидание.** Эти команды обновляют краткоживущий токен с помощью ключа API. `jobs download` ждёт окончания задания, прежде чем заменить сохранённый набор. Если ожидание не удалось или было прервано, прежний набор сохраняется. `delete` применяется только к завершённым заданиям.
- **Получение дополнительных PNG.** Изначально создаётся только первая страница. Обычное скачивание возвращает уже созданные PNG. Используйте, например, `--preview-page 2 5` для создания указанных страниц, проверки их размера и SHA-256 и сохранения. Это не перекомпилирует PDF и не продлевает срок хранения.
- **Досрочное скачивание PDF и повтор SVG.** В заданиях PDF и SVG используйте `--pdf-only` для получения PDF до готовности SVG. Если ошибкой завершилось только извлечение SVG, PDF сохраняется, а результат считается частичным. `retry-svg` повторяет только извлечение. Доступно 8 попыток, включая первую, без продления срока хранения. Если среда выполнения изменилась, создайте новое задание. См. [Доступность PDF до окончания задания и повторное извлечение SVG](/ru/docs/api/#pdfの先行公開とsvgの再試行).
- **Повторные попытки при сетевых сбоях.** При временных ошибках опрос состояния повторяется. Ошибки аутентификации и доступа возвращаются немедленно. Если CLI перестал ждать, сервер может продолжать работу. Проверьте тот же `<jobId>`, прежде чем создавать новое задание. См. [Ожидание и повторные запросы CLI](/ru/docs/reference/#cliの待機と再試行).

## Выходные файлы {#成果物}

О раннем скачивании PDF, выборе страниц PNG и повторном извлечении SVG см. [Получение PDF, PNG и SVG](/ru/docs/outputs/).

| Путь | Содержимое |
| --- | --- |
| `.render/result.pdf` | Успешно созданный PDF |
| `.render/compile.log` | Журнал компиляции LaTeX |
| `.render/errors.json` | Структурированные сведения об ошибках |
| `.render/job.json` | Итоговое состояние задания |
| `.render/previews/page-N.png` | Предварительный просмотр не более чем 100 страниц |
| `.render/svg/manifest.json` | Соответствие SVG положениям в исходниках и координатам PDF |
| `.render/svg/objects/*.svg` | Отдельный SVG для выражения или рисунка TikZ |

## Вывод JSON {#json出力}

Добавьте `--json` к любой команде, чтобы вывести в стандартный поток один объект JSON без сообщений о ходе выполнения. Используется тот же результат `client-core`, что и при обычном выводе. Ключи API и краткоживущие токены исключены.

```sh
n624-latex auth status --json
n624-latex render . --json
n624-latex source upload ./project.zip --json
n624-latex render --source source_... --entrypoint report.tex --output .render/report --json
n624-latex jobs get <jobId> --json
n624-latex jobs download <jobId> --output .render --json
n624-latex doctor --json
```

Схемы для успеха и ошибок, а также коды выхода см. в разделе [Формат JSON в CLI](/ru/docs/reference/#cliのjson形式).
