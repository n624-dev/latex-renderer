## 更新する前に

| 変えたいもの | 操作する場所 |
| --- | --- |
| サーバーのアプリ本体 | **管理 → 更新** |
| TeX Live の版や言語 | **管理 → TeX環境**。[TeX 環境を変更する](/docs/self-hosting/#tex環境の初期設定) |
| 端末の APT パッケージ `n624-latex` | [APT 版の更新](/docs/client/#apt-版の更新) |

更新を始める前に、次の 3 点を確認してください。

1. [暗号化バックアップを手動作成して検証](/docs/backups/#手動で作成する)しておく。
2. 利用者の変換ジョブが落ち着いている時間帯を選ぶ。
3. 保守モードを通常（`normal`）のままにする。更新処理が必要なサービスの停止と起動、変換テストを行います。

## 正式版を適用する

1. 所有者（Owner）アカウントでログインし、**管理 → 更新**（`/admin/updates/`）を開きます。
2. バージョン指定欄を空にしたまま**更新を確認**を押し、現在のバージョンと利用可能な正式版を確認します。
3. **取得・検証して更新**を選び、変更理由を入力して**更新を開始**を押します。
4. 表示された**操作 ID** を控え、ステータスが**正常に完了**になるのを確認します。
   - **アプリ更新済み・Updater切替待ち**と表示された場合は、同じ操作の結果表示と**更新プログラムの詳細**を確認してください。
   - 更新処理はブラウザを閉じても継続します。サービス再起動中に一時的な `502` が表示された場合は、少し待てば自動で再接続されます。
5. 別のブラウザ（またはプライベートウィンドウ）でログインして代表的な文書を変換し、PDF の取得とアプリ・Updater 両方のバージョンを確認します。

`n624-latex admin update status --json` の `toolchain.node` で、稼働中のUpdaterが使用しているNode.jsのバージョンと対応範囲を確認できます。インストール済みのCorepackのバージョンは `toolchain.corepack` に表示されます。取得できない場合は `null` です。

## 通知と自動更新

**更新ポリシー**から、既定の**確認・通知のみ**か、**検証後に自動適用**を選べます。

- 自動適用の対象は正式版（Stable）のみです。
- 自動適用を開始した場合、systemd の更新サービスは同じ更新の完了まで待ちます。アプリと Updater の切り替えまで確認できれば成功し、更新が中断・失敗した場合は失敗を記録します。
- 検証専用環境でリリース候補（RC）を試す場合は、バージョン欄に `vX.Y.Z-rc.N` の形式で公開済みタグを明示指定して適用します。

## 更新が失敗した場合

失敗が表示された場合は、バージョン番号の表示だけで判断せず、**詳細ログ**の操作 ID と失敗段階、現在のアプリと Updater の版、ログイン・変換の可否、および復旧レビュー要否を確認します。

- **`UPDATE_MAINTENANCE_ACTIVE` が表示された場合**：進行中の作業がないか確認し、保守モードを通常（`normal`）に戻してから更新を開始します。
- **`RECOVERY_REVIEW_REQUIRED` が表示された場合**：[更新失敗後の復旧点を確認する](/docs/backups/#更新失敗後の復旧点を確認する)の手順へ進んでください。

## 前の版へ戻す

- **アプリだけを前の版に戻せる場合**：**管理 → 更新**で復旧先を確認し、利用できる場合は **前回へロールバック** を選びます。完了したらログインと PDF 変換を確認します。
- **データベース変更を伴い非互換な場合**：アプリ単体のロールバックはできません。対応する復旧点の DB とストレージを揃えて戻す必要があるため、[データを復旧する場合](/docs/backups/#データを復旧する場合)の手順に従ってください。
