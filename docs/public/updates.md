## 更新する前に

アプリケーションは**管理 → 更新**で、TeX Live のイメージや言語は**管理 → TeX環境**で更新します。TeX 環境だけを変更する場合は[TeX 環境の設定](/docs/self-hosting/#tex環境の初期設定)を参照してください。

アプリケーションを更新する前に[暗号化バックアップを作成して検証](/docs/backups/#手動で作成する)し、実行中の変換が落ち着く時間を選びます。保守モードは通常（`normal`）を選びます。Updater が更新に必要なサービス停止を行い、新バージョンで実際の変換を試すためです。更新前にサービスを手動で停止する必要はありません。

## 正式版を適用する

1. 所有者でサーバーにログインし、**管理 → 更新**（`/admin/updates/`）を開きます。
2. バージョン欄を空にして**更新を確認**を押します。利用できる正式版と現在のバージョンを確認します。
3. **取得・検証して更新**を選び、変更理由を記入して**更新を開始**します。
4. 操作 ID を控え、**正常に完了**を確認します。**アプリ更新済み・Updater切替待ち**の場合は、同じ操作の結果と**更新プログラムの詳細**を確認します。
5. 別のブラウザでログインし、代表的な文書を変換して PDF を取得します。アプリと Updater のバージョンも確認してください。

更新操作は画面を閉じても続きます。再起動中は画面が再接続を試みます。一時的に 502 が出たら、少し待って同じ操作の表示へ戻ります。

## 通知と自動更新

**更新ポリシー**で、既定の**確認・通知のみ**か、**検証後に自動適用**を選択します。自動適用は正式版が対象です。リリース候補を検証専用環境で試す場合は、`vX.Y.Z-rc.N` まで含む公開済みバージョンを指定します。

## 更新が失敗した場合

失敗が表示されたら、**詳細ログ**の操作 ID と失敗段階を確認します。バージョン表示だけで完了を判断せず、現在のアプリ・Updater、ログインと変換の動作、復旧レビューの有無を確認してください。

`UPDATE_MAINTENANCE_ACTIVE` が表示された場合は、進行中の作業を確認して通常の保守モードに戻してから、更新を開始します。`RECOVERY_REVIEW_REQUIRED` が表示された場合は、[更新失敗後の復旧点の確認](/docs/backups/#更新失敗後の復旧点を確認する)に進みます。

## 前の版へ戻す

更新画面で復旧先を確認します。前の版が現在のデータベースと互換で、ロールバックが利用できる場合だけ、**アプリケーション更新**画面から前の版へ戻します。完了後はログインと代表的な変換を確認します。

データベース変更を伴う更新で互換性がない場合は、対応する復旧点のデータベースとストレージをそろえて復旧する必要があります。まず[データを復旧する場合](/docs/backups/#データを復旧する場合)を確認してください。
