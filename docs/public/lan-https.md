## LAN の IP アドレスからアクセスする

Akebi はサーバーのプライベート IP アドレスから HTTPS の名前を作ります。例えばサーバーが `192.168.1.50`、設定したドメインが `lan.example.org` なら、接続先は `https://192-168-1-50.lan.example.org` です。IPv6 は対応するプライベートアドレスの 8 グループを展開した名前になります。セットアップに表示された URL を使ってください。

端末から対象 LAN への通信経路が必要です。名前が解決しない場合は、利用中の DNS がプライベート IP を返す応答を遮断していないか確認します。例外が必要なら、使用する LAN ドメインだけを対象にしてください。

## 証明書の方式を選ぶ

| 方式                            | 必要なもの                                                                                          |
| ------------------------------- | --------------------------------------------------------------------------------------------------- |
| 共通サービス・公開 CA           | 共通サービスの設定と CA 規約への同意。証明書の秘密鍵は導入先に保存                                  |
| 独自サービス・公開 CA           | [独自の Akebi 証明書サービス](/docs/lan-https-authority/)の URL、LAN ドメイン。招待制なら招待コード |
| Keyless                         | 対応する証明書サービス。TLS 接続時の署名をサービスへ委任                                            |
| 手持ちの証明書・プライベート CA | サーバー名と一致する証明書と秘密鍵。プライベート CA は接続する端末とサーバーに CA の信頼設定が必要  |

公開 CA を使う場合、発行された証明書の名前は証明書の透明性ログに記録されます。異なる LAN でも同じ IP アドレスとドメインを使用すると、ブラウザ上は同じ接続先として扱われ、Cookie などの保存領域を共有します。

## LAN 向けに設定する

1. 準備済みのサーバーで[設定ウィザード](/docs/server-setup/)を開きます。管理下の専用 standalone HTTPS から変更する場合は `--ingress` を選びます。
2. **LAN** を選び、実際のネットワークインターフェース、プライベート IP アドレス、接続を許可するサブネット、HTTPS ポートを指定します。
3. 共通または独自の証明書サービスと発行方式を選びます。公開 CA を使う場合は指定された CA の規約を確認します。招待コードが必要な場合は専用欄に入力してください。
4. プレビューで URL と範囲を確認して適用します。アプリのパスワードや OIDC は引き続き使います。
5. 許可した LAN 内の別端末から表示された URL を開き、ログインとサンプルの変換を確認します。

独自サービスを使う場合の DNS・証明書発行は[証明書サービスの構築手順](/docs/lan-https-authority/)を参照してください。

## 証明書の状態を確認する

```bash
systemctl status latex-renderer-lan-https.service latex-renderer-lan-renew.timer
sudo journalctl --namespace=latex-renderer-lan --since '1 hour ago'
```

発行・更新に失敗した場合は、サーバーの時刻、証明書サービスへの HTTPS 接続、設定したドメインと IP、CA が示す再試行時刻を確認します。有効な発行済み証明書は維持され、次のタイマーで記録済みの発行処理を再開できます。鍵と発行状態が合わない場合は、保管した同じ世代の状態を確認してください。
