## 업데이트하기 전에 {#更新する前に}

| 변경할 대상 | 변경 위치 |
| --- | --- |
| 서버 애플리케이션 | **관리 → 업데이트** |
| TeX Live 버전 또는 언어 | **관리 → TeX 환경**. [TeX 환경 변경](/ko/docs/self-hosting/#tex環境の初期設定) 참고 |
| 로컬 APT 패키지 `n624-latex` | [APT 패키지 업데이트](/ko/docs/client/#apt-版の更新) |

다음 세 가지를 확인한 뒤 시작하세요.

1. [암호화된 백업을 수동으로 만들고 검증](/ko/docs/backups/#手動で作成する)합니다.
2. 사용자 변환 작업이 적은 시간을 선택합니다.
3. 유지보수 모드는 정상(`normal`)으로 둡니다. 업데이트 과정에서 필요한 서비스 중지·시작 및 변환 테스트를 수행합니다.

## 정식 버전 적용 {#正式版を適用する}

1. 소유자 계정으로 로그인하고 **관리 → 업데이트**(`/admin/updates/`)를 엽니다.
2. 버전 입력란을 비워 두고 **업데이트 확인**을 눌러 현재 버전과 사용 가능한 정식 버전을 확인합니다.
3. **다운로드·검증 후 업데이트**를 선택하고 변경 사유를 입력한 뒤 **업데이트 시작**을 누릅니다.
4. 표시된 **작업 ID**를 기록하고 상태가 정상 완료인지 확인합니다.
   - 애플리케이션은 업데이트됐지만 업데이터 전환 대기 중이라면 같은 작업의 결과와 업데이터 세부 정보를 확인합니다.
   - 브라우저를 닫아도 업데이트는 계속됩니다. 서비스 재시작 중 일시적으로 `502`가 표시되면 자동으로 재연결될 때까지 기다립니다.
5. 다른 브라우저나 비공개 창에서 로그인하여 대표 문서를 변환합니다. PDF 다운로드 및 애플리케이션과 업데이터의 버전을 각각 확인합니다.

## 알림과 자동 업데이트 {#通知と自動更新}

**업데이트 정책**에서 기본값인 **확인 및 알림만** 또는 **검증 후 자동 적용**을 선택할 수 있습니다.

- 자동 적용은 정식 버전(Stable)만 대상으로 합니다.
- 전용 검증 환경에서 릴리스 후보(RC)를 시험하려면 버전 입력란에 `vX.Y.Z-rc.N` 형식의 공개된 태그를 명시하여 적용합니다.

## 업데이트에 실패한 경우 {#更新が失敗した場合}

상세 로그에서 작업 ID와 실패 단계, 현재 애플리케이션과 업데이터 버전, 로그인·변환 가능 여부, 복구 검토 필요 여부를 확인합니다. 버전 번호만으로 성공 여부를 판단할 수 없습니다.

- **`UPDATE_MAINTENANCE_ACTIVE`.** 진행 중인 유지보수가 있는지 확인하고 유지보수 모드를 `normal`로 돌린 뒤 업데이트를 시작합니다.
- **`RECOVERY_REVIEW_REQUIRED`.** [업데이트 실패 후 복구 지점 확인](/ko/docs/backups/#更新失敗後の復旧点を確認する) 절차를 따르세요.

## 이전 버전으로 되돌리기 {#前の版へ戻す}

- **애플리케이션만 롤백할 수 있는 경우.** **관리 → 업데이트**에서 복구 대상을 확인하고 가능하면 **이전 버전으로 롤백**을 선택합니다. 완료 후 로그인과 PDF 변환을 확인합니다.
- **데이터베이스 변경이 호환되지 않는 경우.** 애플리케이션만 롤백할 수 없습니다. 해당 복구 지점의 DB와 저장소를 함께 되돌려야 하므로 [데이터 복구](/ko/docs/backups/#データを復旧する場合) 절차를 따르세요.

[이전 버전 마이그레이션 및 특수 복구](/ko/docs/reference/#旧版からの移行と特殊復旧)와 [업데이터 구현 규격 및 보관 정책](https://github.com/n624-dev/latex-renderer/blob/main/docs/update-recovery.md)도 참고하세요.
