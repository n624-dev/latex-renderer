## 설정 방식 선택 {#どの手順を使うか}

새 서버는 [서버 준비](/ko/docs/self-hosting/#準備するもの)를 마친 뒤 **브라우저**에서 마법사를 여세요. 기존 서버에서도 같은 마법사로 로그인 방식 및 실행 제한을 바꿀 수 있습니다.

- 서버에서 `sudo n624-latex server setup --plan`을 실행해 필요한 패키지와 여유 공간을 확인합니다. 부족한 항목을 준비한 뒤 다시 실행하세요.
- 기존 전용 HTTPS 또는 LAN HTTPS(Akebi)를 변경하려면 시작 명령에 `--ingress`를 추가합니다.
- 최소 구성 호스트에서 Docker가 커널 모듈 누락을 보고하면 안내를 따라 준비하고 다시 실행합니다. 예를 들어 `nf_tables`가 필요하다고 나오면 관리자가 `sudo modprobe nf_tables`를 실행합니다.

## 브라우저에서 열기 {#ブラウザで開く}

root가 아닌 배포용 계정으로 서버에 SSH 연결한 뒤 다음 명령을 실행합니다. **설정이 끝날 때까지 터미널을 열어 두세요.**

```sh
sudo n624-latex server setup --web
```

1. 처음 구축할 때는 준비할 항목을 확인하고 진행하려면 `PREPARE`를 입력합니다. 서명된 릴리스 다운로드, 서비스 준비, 첫 TeX 실행 환경 구축 및 검증이 끝날 때까지 기다립니다.
2. 터미널에 표시된 일회용 URL을 확인합니다. 유효 시간은 **5분**입니다.
3. 서버의 브라우저에서 열거나 로컬 PC로 같은 포트를 **SSH 포트 포워딩**한 뒤 엽니다. 표시된 포트가 `41234`라면 로컬 PC의 다른 터미널에서 다음 명령을 실행하고 마법사가 표시한 URL을 브라우저에서 엽니다.

```bash
ssh -N -L 127.0.0.1:41234:127.0.0.1:41234 admin@latex.example.com
```

> [!WARNING]
> 설정 URL을 공유하거나 설정 포트를 인터넷이나 리버스 프록시에 노출하지 마세요.

## 미리 보기 및 설정 적용 {#プレビューから適用まで}

1. **공개 방식과 로그인 방식을 선택합니다.** 새 설치에서는 HTTPS와 첫 소유자를 설정합니다. 암호와 OIDC 클라이언트 시크릿은 입력을 숨기는 전용 필드에 입력하세요.
2. **미리 보기를 확인합니다.** 공개 URL과 로그인 방식을 검토합니다. 로그인 방식을 바꿀 때는 기존 방식으로 로그인할 수 있는 동안 전환 후 사용할 소유자 정보를 준비합니다.
3. **설정을 적용합니다.** 서비스 시작 또는 재시작이 끝날 때까지 기다립니다.
4. **로그인하고 PDF를 만듭니다.** 다른 브라우저 창에서 [설치 완료 확인](/ko/docs/self-hosting/#導入完了の確認)을 진행합니다.

새 서버에 암호와 OIDC를 함께 설정할 때는 우선 암호로 소유자를 등록하고 그 소유자에게 OIDC `issuer`와 `subject`를 등록합니다. 실행 제한의 메모리 시작 조건은 작업 시작 전 필요한 여유 RAM이며 실행 중 메모리 상한은 컨테이너가 사용할 수 있는 RAM입니다.

## 중단된 변경 확인 {#中断した変更を確認する}

- 적용 시작 후 브라우저 등의 연결이 끊기면 먼저 같은 작업의 결과를 확인합니다.
- 마법사 프로세스가 종료됐다면 같은 대상을 지정해 다시 시작하고 웹에서 **Recover** 또는 터미널에서 **`RECOVER`**를 선택합니다. 이미 등록된 소유자가 있다면 기존 등록을 사용하여 확인 단계까지 재개합니다. 설정 복구가 DB를 이전 백업으로 되돌리지는 않습니다.
- 복구 파일에는 TLS나 OIDC 비밀 설정이 들어 있을 수 있습니다. 수동으로 편집하지 말고 문의할 때는 화면의 오류 코드와 발생 단계만 전달하세요.

## 터미널에서 열기 {#端末で開く}

```sh
sudo n624-latex server setup --cui
```

기존 서버는 항목별로 변경할 값을 입력합니다. 빈 상태로 Enter를 누르면 현재 값이 유지됩니다. 새 서버에서 자동 LAN HTTPS를 사용하려면 `LAN`을 선택하고 안내를 따릅니다. 초기 사용자 지정 HTTPS 또는 기존 Cloudflare 인그레스를 터미널에서 설정할 때는 표시된 형식대로 JSON 한 줄을 입력합니다. 처음 설정한다면 [브라우저에서 열기](#ブラウザで開く)부터 시작하세요.

### 이전 버전과 수동 배포 {#旧版-手動配置の場合}

> [!DETAILS] server-setup.mjs 직접 실행
>
> APT를 사용하지 않고 전용 사용자, Node.js 및 rootless Docker를 준비하여 `/opt/latex-renderer/current`에 검증된 릴리스를 수동으로 배치했다면 `server-setup.mjs`를 직접 실행합니다. 미구축 서버는 [수동 준비 절차](/ko/docs/self-hosting/#現在の提供状況)를 참고하세요.
>
> | 작업 | 시작 인수 | 조건 |
> | --- | --- | --- |
> | 기존 인증 또는 실행 제한 변경 | `--existing` | 소유자가 등록되어 있고 서비스가 정상 실행 중 |
> | 최초 설정 및 소유자 등록 | `--initial` | 릴리스와 런타임이 준비됐고 운영 설정이나 DB가 아직 없음 |
> | 관리 중인 전용 HTTPS 변경 | `--ingress` | 전용 standalone HTTPS를 사용 중. 기존 공유 Nginx에서의 전환은 별도 작업입니다. |
>
> - **터미널에서 열기**
>   ```bash
>   sudo /usr/local/bin/node /opt/latex-renderer/current/deploy/scripts/server-setup.mjs --cui --existing
>   ```
> - **브라우저에서 열기**
>   ```bash
>   sudo /usr/local/bin/node /opt/latex-renderer/current/deploy/scripts/server-setup.mjs --web --existing
>   ```

구현 세부 사항은 [마법사의 입력 형식과 복구 규격](https://github.com/n624-dev/latex-renderer/blob/main/docs/server-settings-wizard.md)을 참고하세요.
