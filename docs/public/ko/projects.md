## 프로젝트 구성 {#構成}

- **파일 하나로 된 문서.** 웹 앱에 `.tex` 파일을 그대로 올리거나 CLI에서 `n624-latex main.tex`을 실행합니다.
- **이미지, 참고문헌 또는 여러 소스 파일이 있는 문서.** 상대 경로를 유지하여 **하나의 ZIP**으로 묶습니다. CLI에서는 폴더를 직접 지정할 수도 있습니다.
- **ZIP 만들기.** 부모 폴더 대신 그 안의 `main.tex`, `images/` 등을 선택해 압축합니다. 부모 폴더를 포함했다면 변환할 때 `project/main.tex`과 같은 상대 경로를 진입점으로 지정합니다.

```text
project/
├─ main.tex
├─ references.bib
├─ images/
│  └─ figure.png
└─ styles/
   └─ local.sty
```

**진입점과 상대 경로의 기준**
기본 진입점은 프로젝트 루트의 `main.tex`입니다. 하위 폴더의 `.tex` 파일(예: `docs/main.tex`)을 지정해도 **컴파일 작업 디렉터리는 항상 프로젝트 루트**입니다. 예를 들어 `docs/main.tex`에서 같은 폴더의 `body.tex`을 읽으려면 `\input{docs/body.tex}`이라고 작성합니다. `\input{body.tex}`이라고 쓰면 루트 바로 아래의 `body.tex`을 찾습니다.

## 최소 일본어 문서 예제 {#日本語の最小例}

기본 엔진은 **LuaLaTeX**입니다. 다음 내용을 UTF-8 인코딩의 `main.tex`로 저장하여 일본어 문서를 시험할 수 있습니다.

```latex
\documentclass{ltjsarticle}
\begin{document}
日本語とEnglishを含む文書です。
\end{document}
```

[렌더링 환경](/app/environment/)에서 제공되는 패키지와 글꼴을 검색할 수 있습니다. 배포 시 실제 렌더러 컨테이너에서 생성한 목록이며 Remote MCP도 같은 목록을 검색합니다. 필요한 패키지가 없다면 `compile.log`의 관련 메시지를 서버 관리자에게 전달하세요.

## 저장된 프로젝트와 버전 {#保存projectと改訂}

웹 앱(`/app/`)에서 변환한 문서는 프로젝트에 저장됩니다.

- **자동 버전 기록.** 같은 프로젝트에서 내용, 메인 문서, 엔진, 출력 형식의 조합이 달라지면 새 버전이 저장됩니다. 이전 버전은 프로젝트 기록에 남습니다.
- **이전 버전 변환.** **다시 변환**을 누르면 해당 버전의 문서와 엔진으로 실행합니다. 여기서 출력 형식을 변경하면 같은 버전의 변환 기록에 결과를 추가합니다.
- **도구 간 공유와 삭제.** 같은 사용자의 웹 앱, CLI, HTTP API 및 MCP가 저장된 프로젝트와 버전을 공유합니다. 프로젝트 삭제는 목록에서 기록을 숨기는 작업입니다. 기존 입력과 결과는 각각의 보관 기한에 따라 정리합니다. 즉시 완전 삭제해야 하면 관리자에게 문의하세요. 유효한 버전이 참조하는 입력도 사용자 저장 용량에 포함됩니다. [공유 및 보관 규칙](/ko/docs/reference/#保存プロジェクトの共有-保持)을 참고하세요.

### 브라우저에서 편집 {#ブラウザーで編集する}

저장한 프로젝트를 열고 **TeX 편집**을 선택합니다. 변경 사항은 초안에 자동 저장됩니다. 입력을 멈추면 컴파일이 시작되고 성공 시 PDF가 갱신됩니다. 미리 보기 컴파일이 실패하면 마지막으로 표시한 PDF와 그 초안 버전을 확인할 수 있습니다.

새 프로젝트는 비어 있는 `main.tex`로 시작합니다. 본문이 비어 있으면 템플릿을 선택할 수 있습니다. 이전 버전으로 편집하려면 **이 버전에서 편집**을 선택합니다. 작업 중인 초안이 있으면 확인한 뒤 교체합니다.

필요할 때만 컴파일하려면 **자동 컴파일**을 끄고 **컴파일**을 누릅니다. **저장할 버전의 출력 설정**을 선택한 뒤 **버전 저장**을 누르면 현재 초안과 출력 설정을 함께 저장합니다. SVG가 필요할 때는 저장한 버전에서 **다시 변환**을 누르세요.
편집 중인 컴파일의 진행 상태와 미리 보기는 편집기에서 확인합니다.

## 업로드에서 제외되는 파일 {#送信から除外されるもの}

- **자동 제외.** CLI는 `.git`, `.render` 및 LaTeX가 생성한 보조 파일(예: `.aux`)을 제외합니다. 심볼릭 링크는 허용하지 않습니다.
- **지원하지 않는 파일.** `node_modules` 등 불필요한 폴더를 프로젝트 밖으로 옮기세요. 폴더 업로드 중 지원하지 않는 확장자가 발견되면 CLI는 경로를 표시하고 중지합니다. `README.md` 같은 파일을 프로젝트 안에 유지하면서 제외하려면 루트의 `.latexrenderignore`에 `README.md`를 적습니다. 서버도 같은 확장자 규칙으로 ZIP을 검증합니다.
- **지원 확장자**(대소문자 구분 없음)
  `.tex`, `.sty`, `.cls`, `.bib`, `.bst`, `.csv`, `.dat`, `.txt`, `.png`, `.jpg`, `.jpeg`, `.pdf`
  `.bst`는 BibTeX 참고문헌 스타일 파일이며 하위 폴더에도 둘 수 있습니다. 사용자 정의 스타일 등의 확장자가 목록에 없다면 확장자를 임의로 바꾸지 말고 관리자에게 문의하세요.

## 제한 {#制限}

- **파일 수.** 최대 500개.
- **기본 크기 제한.** 업로드 ZIP 20 MiB, 압축 해제 후 합계 100 MiB, 파일당 20 MiB.
- **진입점.** 입력 소스 내의 상대 `.tex` 경로이며 기본값은 루트의 `main.tex`입니다.
- **보안.** 셸 이스케이프(`\write18` 등), 외부 명령 실행, 외부 네트워크 통신을 모두 차단합니다.
- **리소스.** 처리 시간, 사용자별 저장 용량 및 결과 보관 기간에는 관리자가 설정한 한도가 적용됩니다.
