## 更新前的准备 {#更新する前に}

| 更改内容 | 操作位置 |
| --- | --- |
| 服务器应用 | **管理 → 更新** |
| TeX Live 版本或语言 | **管理 → TeX 环境**。参见[更改 TeX 环境](/zh-CN/docs/self-hosting/#tex環境の初期設定)。 |
| 本机 APT 软件包 `n624-latex` | [更新 APT 版](/zh-CN/docs/client/#apt-版の更新) |

开始更新前请确认以下三项。

1. [手动创建并验证加密备份](/zh-CN/docs/backups/#手動で作成する)。
2. 选择用户转换作业较少的时间段。
3. 保持维护模式为正常（`normal`）。更新程序会按需停止和启动服务，并执行转换测试。

## 应用正式版本 {#正式版を適用する}

1. 以所有者账号登录，打开**管理 → 更新**（`/admin/updates/`）。
2. 将版本号留空，点击**检查更新**，查看当前版本和可用的正式版。
3. 选择**下载、验证并更新**，输入变更原因，然后点击**开始更新**。
4. 记下**操作 ID**，确认状态显示成功完成。
   - 如果显示应用已更新、等待切换更新程序，请检查同一操作的结果及更新程序详情。
   - 关闭浏览器后更新仍会继续。如果服务重启期间暂时出现 `502`，请稍候，界面会自动重新连接。
5. 在其他浏览器或隐私窗口中登录并转换一份典型文档，确认 PDF 可以下载，并检查应用和更新程序各自的版本。

## 通知和自动更新 {#通知と自動更新}

在**更新策略**中，可选择默认的**仅检查并通知**或**验证后自动应用**。

- 自动应用仅适用于正式版（Stable）。
- 要在专用验证环境试用候选版本（RC），请在版本栏明确指定形如 `vX.Y.Z-rc.N` 的已发布标签。

## 更新失败 {#更新が失敗した場合}

打开详细日志，核对操作 ID、失败阶段，以及应用和更新程序的当前版本。还要检查是否能登录和转换、是否需要恢复审查，避免只根据显示的版本号判断。

- **出现 `UPDATE_MAINTENANCE_ACTIVE`。** 确认没有进行中的维护工作，将维护模式改回 `normal`，再启动更新。
- **出现 `RECOVERY_REVIEW_REQUIRED`。** 按[更新失败后检查恢复点](/zh-CN/docs/backups/#更新失敗後の復旧点を確認する)中的步骤操作。

## 回滚到上一版本 {#前の版へ戻す}

- **仅需回滚应用。** 在**管理 → 更新**中确认目标版本。如果可以回滚，请选择**回滚到上一版本**，完成后验证登录和 PDF 转换。
- **数据库存在不兼容变更。** 无法仅回滚应用。必须将数据库和存储恢复至相应恢复点，参见[恢复数据](/zh-CN/docs/backups/#データを復旧する場合)。

参见[旧版迁移与特殊恢复](/zh-CN/docs/reference/#旧版からの移行と特殊復旧)和[更新程序实现规范及保留策略](https://github.com/n624-dev/latex-renderer/blob/main/docs/update-recovery.md)。
