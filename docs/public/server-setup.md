## どの手順を使うか

初めて構築する場合は [サーバーの準備](/docs/self-hosting/#準備するもの)を済ませ、**ブラウザ**でウィザードを開きます。既存サーバーでも同じウィザードでログイン方法や実行制限を変更できます。

- 構築前に必要なパッケージと空き容量を確認するには、サーバーで `sudo n624-latex server setup --plan` を実行します。不足項目が表示されたら準備してから再実行してください。
- 既存の専用 HTTPS や LAN HTTPS（Akebi）を変更するには、起動コマンドに `--ingress` を追加します。
- 最小構成のホストで Docker がカーネルモジュール不足を報告したら、表示された手順で準備してから再実行します。たとえば `nf_tables` が必要と表示されたら、管理者が `sudo modprobe nf_tables` を実行します。

## ブラウザで開く

非 root のデプロイ用アカウントでサーバーに SSH 接続し、次を実行します。**設定が終わるまで端末を開いておきます。**

```sh
sudo n624-latex server setup --web
```

1. 新規構築では、表示された準備内容を確認し、進める場合は `PREPARE` と入力します。署名付きリリースの取得、サービスの準備、最初の TeX 実行環境の構築・検証が完了するまで待ちます。
2. 端末に表示された一回限りの専用 URL（有効期限 **5 分**）を確認します。
3. サーバー上のブラウザで開くか、手元の PC に同じポートを **SSH ポート転送**して開きます。表示されたポートが `41234` の場合は、手元の PC の別ターミナルで次を実行します。その後、ウィザードが表示した URL をブラウザで開きます。

```bash
ssh -N -L 127.0.0.1:41234:127.0.0.1:41234 admin@latex.example.com
```

> [!WARNING]
> 表示されたセットアップ URL を他人に共有したり、セットアップ用ポートをインターネットやリバースプロキシへ公開したりしないでください。

## プレビューから適用まで

1. **公開方法とログイン方法を選ぶ。** 新規構築では HTTPS と最初の管理者（Owner）を設定します。パスワードや OIDC の Client Secret は専用の非表示入力欄に入力します。
2. **プレビューを見る。** 公開 URL とログイン方法を見直します。変更する場合は、現在ログインできるうちに切り替え後の所有者情報を用意します。
3. **設定を適用する。** サービスの起動または再起動が完了するまで待ちます。
4. **ログインして PDF を作る。** 別のブラウザのウィンドウで [導入完了の確認](/docs/self-hosting/#導入完了の確認)を行います。

パスワードと OIDC を併用して新規構築するときは、まずパスワードで所有者を登録し、続いてその所有者に OIDC の `issuer` と `subject` を登録します。実行制限も設定する場合、「メモリの開始条件」はジョブ開始前の空き RAM、「実行中のメモリ上限」はコンテナが使える RAM です。

## 中断した変更を確認する

- 適用開始後にブラウザ等の接続が切れた場合は、まず同じ操作の結果を確認してください。
- ウィザードのプロセス自体が終了した場合は、同じ対象でウィザードを再起動し、Web の **Recover** または端末の **`RECOVER`** を選びます（所有者が登録済みなら既存の登録を使って確認ステップまで再開します。なお、この設定復旧がデータベースを過去のバックアップへ巻き戻すことはありません）。
- 復旧用ファイルには TLS や OIDC の機密設定が含まれる場合があるため手動で編集せず、問い合わせ時は画面のエラーコードと発生段階だけを伝えてください。

## 端末で開く

```sh
sudo n624-latex server setup --cui
```

既存サーバーの設定を変更するときは、項目ごとに入力します。値を維持する項目は空欄のまま Enter を押します。初回セットアップで LAN の自動 HTTPS を使うときは、入力欄で `LAN` を選ぶと端末の案内に沿って設定できます。初回の独自 HTTPS や既存の Cloudflare 公開経路を端末で設定する場合は、表示された形式の JSON を 1 行で入力します。この構成を初めて設定する場合は [ブラウザで開く](#ブラウザで開く)から始めてください。

### 稼働中のキュー上限を変更する

管理CLIで現在の実効値と単位を確認できます。例えば、待機中や実行中など、未完了ジョブの全体上限を50件に変更するには次を実行します。

```sh
n624-latex admin system config
n624-latex admin system config set max_queue_length 50 --reason "Queue capacity review" --yes
```

変更には管理APIの書き込み権限が必要です。設定キー、最小値と最大値は `system config` の結果に表示されます。

### 旧版・手動配置の場合

> [!DETAILS] server-setup.mjs を直接実行する手順
>
> APT を使わず、専用ユーザー・Node.js・rootless Docker を用意して `/opt/latex-renderer/current` に検証済みリリースを手動配置したサーバーでは、`server-setup.mjs` を直接呼び出します（未構築サーバーの手動準備は[セルフホストの手動手順](/docs/self-hosting/#現在の提供状況)を参照）。
>
> | したいこと | 起動時の引数 | 条件 |
> | --- | --- | --- |
> | 既存の認証や実行制限を変更 | `--existing` | 所有者が登録済みで、サービスが正常稼働中 |
> | 初めて設定と所有者を登録 | `--initial` | 準備済みリリースと Runtime があり、運用中の設定や DB が未作成 |
> | 管理下の専用 HTTPS を変更 | `--ingress` | 専用の standalone HTTPS を使用中（既存の共有 Nginx からの移行は別作業） |
>
> - **端末（CUI）で開く場合**：
>   ```bash
>   sudo /usr/local/bin/node /opt/latex-renderer/current/deploy/scripts/server-setup.mjs --cui --existing
>   ```
> - **ブラウザ（Web）で開く場合**：
>   ```bash
>   sudo /usr/local/bin/node /opt/latex-renderer/current/deploy/scripts/server-setup.mjs --web --existing
>   ```

実装詳細：[ウィザードの入力形式と復旧の実装仕様](https://github.com/n624-dev/latex-renderer/blob/main/docs/server-settings-wizard.md)
