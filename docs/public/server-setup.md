## どの手順を使うか

`n624-latex` パッケージ導入済みのサーバーでは、管理者の端末から次のコマンドを実行し、そのまま端末で進めるかブラウザで開くかを選びます。

```sh
sudo n624-latex server setup
```

- **初回構築に必要な準備**：[APT パッケージ `n624-latex`](/docs/client/)、rootless extras を含む Docker Engine、Nginx をインストールします。ファイアウォールや Cloudflare Tunnel を使う場合は、管理者が事前に設定します。既存サーバーでは通常の更新で同コマンドが利用可能になります。
- 最小構成のホストで Docker がカーネルモジュール不足を報告した場合は、表示された手順で準備してからセットアップを再実行します。たとえば `nf_tables` を要求された場合は、管理者が `sudo modprobe nf_tables` を実行します。
- **よく使うオプション**：
  - 変更内容・前提条件・空き容量の事前確認のみ行う：`sudo n624-latex server setup --plan`
  - 管理下の専用 standalone HTTPS や LAN HTTPS（Akebi）を変更する：`sudo n624-latex server setup --ingress`
  - 中断後に再開・復旧する：同じコマンドを再実行し、表示される復旧メニュー（`RECOVER`）を選びます。

### 旧版・手動配置の場合

> [!DETAILS] server-setup.mjs を直接実行する手順
>
> APT を使わず、専用ユーザー・Node.js・rootless Docker を用意して `/opt/latex-renderer/current` に検証済みリリースを手動配置したサーバーでは、`server-setup.mjs` を直接呼び出します（未構築サーバーの手動準備は[セルフホストの手動手順](/docs/self-hosting/#現在の提供状況)を参照）。
>
> | したいこと | 起動時の引数 | 条件 |
> | --- | --- | --- |
> | 既存の認証や実行制限を変更 | `--existing` | 所有者が登録済みで、サービスが正常稼働中 |
> | 初めて設定と所有者を登録 | `--initial` | 準備済みリリースと Runtime があり、運用中の設定や DB が未作成 |
> | 管理下の専用 HTTPS を変更 | `--ingress` | 専用の standalone HTTPS を使用中（既存の共有 Nginx からの移行は別作業） |
>
> - **端末（CUI）で開く場合**：
>   ```bash
>   sudo /usr/local/bin/node /opt/latex-renderer/current/deploy/scripts/server-setup.mjs --cui --existing
>   ```
> - **ブラウザ（Web）で開く場合**：
>   ```bash
>   sudo /usr/local/bin/node /opt/latex-renderer/current/deploy/scripts/server-setup.mjs --web --existing
>   ```

## 端末で開く

ウィザード起動時に端末（CUI）を選ぶと、現在値と変更案が画面に表示されます。

1. パスワードや OIDC の Client Secret などは、画面に文字が残らない専用の非表示入力欄から入力します。
2. プレビュー内容を確認し、問題なければ画面に案内された確認語を入力して適用します。

## ブラウザで開く

SSH でサーバーに接続してウィザードの Web モードを起動し、**完了するまで端末を開いたままにします**。

1. 端末に表示された一回限りの専用 URL（有効期限 **5 分**）を確認します。
2. サーバー上のブラウザで直接開くか、手元の PC から同じポートを **SSH ポート転送**して開きます。たとえば表示されたポートが `41234` の場合、手元の PC の別ターミナルで次を実行し、案内された元の URL をそのままブラウザで開きます。

```bash
ssh -N -L 127.0.0.1:41234:127.0.0.1:41234 admin@latex.example.com
```

> [!WARNING]
> 表示されたセットアップ URL を他人に共有したり、セットアップ用ポートをインターネットやリバースプロキシへ公開したりしないでください。

## プレビューから適用まで

1. **変更項目の入力**：認証方式、メモリ条件、変換タイムアウトなどを設定します。認証方式を切り替える場合は、現在の認証が使えるうちに切り替え後の所有者情報を用意しておきます（パスワードと OIDC を併用して初回導入する場合は、まずパスワードで最初の所有者を登録し、その後で所有者に OIDC の `issuer` と `subject` を明示登録します）。
2. **プレビューの確認**：変更差分を確認します。なお、「メモリの開始条件」はジョブ開始前にホストに必要な空き RAM 量であり、「実行中のメモリ上限」（コンテナが最大で使える RAM 量）とは別の設定です。
3. **適用**：確認して適用します（設定反映のためサービスが一時的に再起動する場合があります）。
4. **動作確認**：別のプライベートウィンドウ等で所有者としてログインし、利用者画面でサンプル文書を変換できるか確認します。

## 中断した変更を確認する

- 適用開始後にブラウザ等の接続が切れた場合は、まず同じ操作の結果を確認してください。
- ウィザードのプロセス自体が終了した場合は、同じ対象でウィザードを再起動し、Web の **Recover** または端末の **`RECOVER`** を選びます（所有者が登録済みなら既存の登録を使って確認ステップまで再開します。なお、この設定復旧がデータベースを過去のバックアップへ巻き戻すことはありません）。
- 復旧用ファイルには TLS や OIDC の機密設定が含まれる場合があるため手動で編集せず、問い合わせ時は画面のエラーコードと発生段階だけを伝えてください。
