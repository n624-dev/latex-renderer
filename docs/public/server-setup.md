## どの手順を使うか

初めてサーバーを準備する場合は[セルフホストの初回導入](/docs/self-hosting/#現在の提供状況)から始めます。このページのウィザードは、専用ユーザー、Node.js、rootless Docker などが準備され、検証済みでビルドされたリリースを `/opt/latex-renderer/current` に配置済みのサーバーが対象です。

| したいこと                 | 起動時の指定 | 条件                                                                      |
| -------------------------- | ------------ | ------------------------------------------------------------------------- |
| 既存の認証や実行制限を変更 | `--existing` | 所有者が登録済みで、サービスが正常                                        |
| 初めて設定と所有者を登録   | `--initial`  | 準備済みリリースと利用する Runtime があり、運用中の設定や DB が存在しない |
| 管理下の専用 HTTPS を変更  | `--ingress`  | 専用の standalone HTTPS を使用中。既存の共有 Nginx からの移行は別作業     |

Ubuntu／Debian のパッケージ導入、Docker の作り直し、ファイアウォールや Cloudflare の設定は事前に管理者が行います。Cloudflare を選ぶ場合は、すでに用意した Tunnel と公開 HTTPS を使用します。

## 端末で開く

管理者の端末から実行します。この例は既存設定を開きます。対象に応じて最後の引数を表の値に置き換えます。

```bash
sudo /usr/local/bin/node /opt/latex-renderer/current/deploy/scripts/server-setup.mjs --cui --existing
```

表示された現在値と変更案を確認します。パスワードや OIDC のクライアントシークレットは別の非表示入力欄を使います。内容が正しければ、表示された確認語を入力して適用します。

## ブラウザで開く

SSH でサーバーに接続し、次を実行して端末を開いたままにします。

```bash
sudo /usr/local/bin/node /opt/latex-renderer/current/deploy/scripts/server-setup.mjs --web --existing
```

表示された URL は一度だけ使え、5 分で失効します。サーバー上のブラウザで開くか、別の端末から同じポートを SSH 転送します。たとえば URL のポートが `41234` なら、手元の端末で次を実行し、元の URL をそのまま開きます。

```bash
ssh -N -L 127.0.0.1:41234:127.0.0.1:41234 admin@latex.example.com
```

URL は共有せず、セットアップ用のポートをインターネットやプロキシへ公開しないでください。

## プレビューから適用まで

1. 認証方式、メモリや変換時間など、変更する項目を選びます。変更後の認証で使う所有者の情報を、現在の認証が使えるうちに用意します。
2. プレビューで変更箇所を確認します。メモリの開始条件はジョブ開始前に必要な空き RAM です。実行中のメモリ上限は別の設定で、ジョブは必要に応じてその上限まで使います。
3. 確認後に適用します。設定変更でサービスが一時的に再起動する場合があります。
4. 別のブラウザウィンドウで所有者としてログインし、利用者の画面でサンプルを変換します。

パスワードと OIDC を併用して初回導入する場合は、パスワードで最初の所有者を登録し、その後で所有者に OIDC の issuer と subject を明示的に登録します。

## 中断した変更を確認する

適用後に画面が切断されたら、同じ操作の結果を確認してください。プロセスを終了した場合は、同じ対象でウィザードを起動し、Web の **Recover** または端末の `RECOVER` を選びます。所有者を登録済みなら、既存の登録を使って確認まで再開します。設定の復旧でデータベースを過去のバックアップに戻すことはありません。

復旧用ファイルには TLS や OIDC の設定が含まれる場合があります。手で編集せず、問い合わせには画面に表示されたエラーと発生段階だけを添えてください。
