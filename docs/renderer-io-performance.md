# レンダリングのI/O計測

`renderer-image` の手動実行で `io_benchmark: true` を指定すると、検証済みの
一時Runtimeを再利用し、1・10・50・100ページのPDF／PDF+SVGを計測します。
比較試験は使い捨てのGitHub-hosted Runner専用です。共有サーバーでは実行しません。
生成ファイルは終了時に回収し、永続的なActions cacheは追加しません。

## 基準値

[基準実行](https://github.com/n624-dev/latex-renderer/actions/runs/39194458574)
（amd64、TeX Live 2026-10-17、コミット `e8fff10`）の全ページPNG生成方式です。
比較用文書の値であり、実サービスのすべての文書を代表するものではありません。

| ページ | PDF全体 | PDF+SVG全体 |         PNG合計 | PDF成果物の検証・公開 |
| ------ | ------: | ----------: | --------------: | --------------------: |
| 1      |     2秒 |         3秒 |    13,655 bytes |                 6.9ms |
| 10     |     2秒 |         4秒 |   139,558 bytes |                12.1ms |
| 50     |     5秒 |         7秒 |   721,788 bytes |                33.5ms |
| 100    |     8秒 |        12秒 | 1,456,392 bytes |                56.5ms |

100ページではPNG生成だけで6〜7秒を使用しました。プレビューの必要時生成と、
成果物検証の読み直し削減は、異なる工程の改善です。

必要時生成のAPI・クライアント・容量と復旧の条件は
[PDFプレビュー](lazy-previews.md) を参照してください。
新方式の比較は同じPDFから全ページを生成する対照と、初回／要求ページのバイト比較を含みます。
比較結果が得られる前に改善率を保証することはありません。

[必要時生成の比較実行](https://github.com/n624-dev/latex-renderer/actions/runs/39206403150)
（amd64、TeX Live 2026-10-17、`8245c9d`）は全体が成功しました。
旧方式の対照は、同じRuntimeと同じ完成PDFから全ページをPNG化しています。

| ページ | 新PDF全体 | 新PDF+SVG全体 |            初回PNG | 同一PDFの全ページPNG対照 |
| ------ | --------: | ------------: | -----------------: | -----------------------: |
| 1      |       1秒 |           3秒 | 13,655 bytes / 1枚 |       13,655 bytes / 1枚 |
| 10     |       2秒 |           4秒 | 13,655 bytes / 1枚 |     139,558 bytes / 10枚 |
| 50     |       3秒 |           4秒 | 13,655 bytes / 1枚 |     721,788 bytes / 50枚 |
| 100    |       2秒 |           5秒 | 13,655 bytes / 1枚 |  1,456,392 bytes / 100枚 |

全8ケースで初回PNGと明示要求した最終ページのPNGが、全ページ生成した対照と
バイト単位で一致しました。100ページの全ページPNG対照は8秒・約8.2CPU秒でした。
初回生成の削減効果を示す単発比較であり、別実行の基準値との時間差をすべて
本変更の効果とはみなしません。カーネル・キャッシュ・Runnerの変動を含みます。

## 検証済みSourceの読み取り専用再利用

[比較工程](https://github.com/n624-dev/latex-renderer/actions/runs/39206552434)
は成功しましたが、この実行全体はテストimportの不備で失敗しています。
同じRunner上の3回の中央値です。ページキャッシュが温まった条件であり、
冷間I/Oや本番の待ち時間を保証する数値ではありません。

| Source                   | 完全検証＋展開 | 全ファイル再検証 | 初回展開＋manifest記録 | 追加保持する入力 |
| ------------------------ | -------------: | ---------------: | ---------------------: | ---------------: |
| 小規模3ファイル          |         3.74ms |           2.17ms |                 7.07ms |        195 bytes |
| 402ファイル              |       232.07ms |          93.29ms |               332.48ms |    409,731 bytes |
| 16MiB画像を含む3ファイル |        54.10ms |          14.26ms |                61.67ms | 16,777,347 bytes |

再検証工程の追加書き込みブロックは0でした。保持量の表は論理サイズであり、
実際の予算には割当ブロック・ディレクトリ・manifest・DB余裕を含めます。
初回負担と追加保存量があるため、容量上限と期限なしの保存にはしません。
実装条件は [Source入力の再利用](source-input-reuse.md) を参照してください。

## 成果物の単一パス検証

[比較実行](https://github.com/n624-dev/latex-renderer/actions/runs/39195818639)
のベンチマーク工程は成功しましたが、この実行全体はlintで失敗しています。
成功したCI全体の結果としては扱いません。

同一fixtureの走査・形式検証・SHA-256・コピー・コピー後の照合を比較した結果です。
各fixtureは4MiBのPDF、100個のSVG、指定数のPNGを含みます。

| PNG数 | 従来方式 | 単一パス＋CoW要求 | CoWの実対応        |
| ----- | -------: | ----------------: | ------------------ |
| 1     |  148.5ms |           118.1ms | 非対応・通常コピー |
| 20    |  166.3ms |           115.4ms | 非対応・通常コピー |
| 100   |  259.2ms |           218.5ms | 非対応・通常コピー |

この単発比較では単一パス方式が速く、出力の全SHA-256も一致しました。
順序・ページキャッシュ・ファイルシステムによる変動があるため、一定の改善率は保証しません。
CoW対応ファイルシステムでの高速化は、この結果では未検証です。

既定の検証は同じファイル記述子で署名部・SVG構造・SHA-256を検査します。
SVGは逐次解析し、PDF／PNG／SVGを追加の全量バッファには読み込みません。
走査後のinode・リンク数・サイズ・更新時刻が変化した場合は拒否します。
候補へのコピーには `COPYFILE_FICLONE | COPYFILE_EXCL` を指定します。
CoW非対応時の通常コピーは[Node.jsの定義](https://nodejs.org/docs/latest-v24.x/api/fs.html#fspromisescopyfilesrc-dest-mode)に従い、
容量不足・既存ファイル・その他のコピー失敗を成功には置き換えません。
ハードリンク共有、検証の省略、確定世代の上書きは行いません。

## 指標の読み方

- `RENDERER_METRIC` は工程の経過秒、コンテナの累積CPU・I/O・メモリ高水位、
  工程境界での一時容量を記録します。経過秒は1秒単位であり、一時容量は厳密な最大値ではありません。
- `RENDERER_IO_BENCHMARK` はNode側のwall／CPU／カーネルI/Oブロック数と
  scan／format／hash／copyを記録します。最大RSSはそのプロセスの生存期間の高水位です。
- 通常CIでは小規模Source3種と成果物fixtureを比較します。
  実際のTeX比較には上記の任意実行を使い、変更前後のcommit・architecture・日付を揃えます。
- 生成物の全バイト照合は比較試験にも含めます。速さだけを理由にvalidationを省略しません。
