# Renderer sandbox

The image pins Debian by digest and installs TeX Live 2026 with Japanese and English language collections plus the main TeX/LaTeX, fonts, math, graphics, publishing, bibliography, LuaTeX, XeTeX, context, metapost, music, games, and generic collections. TeX Live's Japanese collection pulls its generic CJK support dependency, but the Chinese and Korean language collections are not selected. Documentation/source trees and unrelated language packs are omitted to preserve disk. The verified local image ID is `sha256:899050e621ee05845a3a435aeeec789d77a78f2d2f44f8579b0ab8c0fd848620` (4,678 installed TeX packages, approximately 4.27 GB).

Runtime uses a one-shot rootless container with `--network none`, read-only root, fixed non-root UID/GID 10000, `--cap-drop ALL`, no-new-privileges, seccomp, PID/CPU/RAM/swap limits, a bounded noexec tmpfs, read-only input, and job-only output. Docker rootless mode does not support AppArmor, so production does not pass a misleading AppArmor option; the optional profile is reserved for explicitly approved rootful development tests. Rootless user-namespace mappings access only world-readable extracted inputs and a world-writable staging mount; both remain beneath a host directory traversable only by the dedicated `latex-renderer` group. Published artifacts are revalidated before exposure. `latexmk` is fixed to LuaLaTeX with no shell escape and `openin_any/openout_any=p`. The worker never mounts a Docker socket into the container.

Production requires rootless Docker. Rootful override exists only for an isolated development smoke test. Images/PDFs and Poppler execute inside the same sandbox boundary as TeX.
